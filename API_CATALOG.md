# TalentMAP API catalog

Comprehensive inventory of the TalentMAP API's domain model, REST endpoints,
authentication surface, and permission controls.  Generated by automated
codebase analysis to support skills cataloging and governance review.

---

## System overview

TalentMAP is the Department of State's Foreign Service bidding and workforce
management system.  It matches Foreign Service Officers (FSOs) to overseas and
domestic assignments based on skills, language qualifications, grade, and
organizational fit.  The API backend is built on **Django 2.2 / Django REST
Framework** with SAML2 SSO and token-based authentication.

### Key domain concepts

| Concept | Description |
|---------|-------------|
| **Position** | A specific post/job that combines grade, skill, language requirements, organization, and geographic location |
| **Skill** | A 4-character code representing a job specialty (e.g., ECON, CONS, MGMT). Skills are grouped into **Skill Cones** |
| **Grade** | Foreign Service rank (CA, CM, MC, OC, 01–08), with career ambassador (CA) as the highest |
| **Bid Cycle** | A time-bounded period during which FSOs submit bids for available positions |
| **Bid** | An FSO's expression of interest in a position within a bid cycle; progresses through statuses: draft → submitted → handshake offered → handshake accepted → in panel → approved/declined |
| **Tour of Duty** | The standard assignment duration at a post (12, 24, or 36 months) |
| **Language Qualification** | Combination of a language + reading proficiency + spoken proficiency (ILR scale: 0 to 5) |
| **CDO** | Career Development Officer — manages a portfolio of FSOs and their bidding activity |
| **6/8 Rule** | Service requirement ensuring FSOs alternate between domestic and overseas tours |
| **FSBid** | External Foreign Service Bidding system that TalentMAP integrates with via SOAP |

## Authentication and authorization

### Authentication mechanisms

| Mechanism | Module | Description |
|-----------|--------|-------------|
| **ExpiringToken** | `rest_framework_expiring_authtoken` | Primary API auth; tokens expire after 15 min of inactivity (STIG V-220630) |
| **SAML2 SSO** | `djangosaml2` | Enterprise SSO via State Department IdP; POST binding to `/saml2/acs/` |
| **Session** | Django sessions | Used for browsable API; 15-min inactivity timeout with `SESSION_SAVE_EVERY_REQUEST` |

### Permission model

| Permission Class | Scope | Used By |
|-----------------|-------|---------|
| `IsAuthenticated` | Any logged-in user | Profile, notifications, favorites, feedback |
| `IsAuthenticatedOrReadOnly` | Read = public, write = authenticated | Positions, skills, grades, organizations, cycle positions, glossary |
| `isDjangoGroupMember('bidder')` | FSOs with active bidding rights | Bid list operations, bid submissions |
| `isDjangoGroupMember('bureau_ao')` | Bureau Assignment Officers | Position waivers, highlights, bid approvals, assignment history |
| `isDjangoGroupMember('bidcycle_admin')` | Cycle administrators | Bid cycle CRUD |
| `isDjangoGroupMember('feedback_editors')` | Feedback moderators | Feedback administration |
| `isDjangoGroupMember('superuser')` | System administrators | Group/permission management |
| `isDjangoGroupMember('glossary_editors')` | Content editors | Glossary CRUD |

### Role hierarchy

```
superuser
├── bidcycle_admin
├── bureau_ao (per-bureau: bureau_ao:<org_code>)
├── feedback_editors
├── glossary_editors
└── bidder (all active FSOs)
```

## External integrations

| System | Protocol | Purpose |
|--------|----------|---------|
| **FSBid (IPMS)** | SOAP/XML | Primary data source for positions, organizations, locations, bid seasons |
| **State Department IdP** | SAML2 | Single sign-on authentication |
| **TalentMAP Frontend** | REST/JSON | React SPA at `talentmap.state.gov` |

### SOAP synchronization pipeline

```
FSBid (IPMS SOAP) → SynchronizationJob → XMLloader → Django ORM
                                       ↕
                    Scheduled via cron (delta_synchronization)
                    Paginated via PaginationStartKey
                    Models: positions, organizations, locations,
                            languages, grades, skills, posts
```

## Data flow: bidding lifecycle

```
1. BidCycle created (bidcycle_admin)
      ↓
2. Positions added to cycle → CyclePosition records
      ↓
3. FSOs browse positions (filtered by skill, grade, language, location)
      ↓
4. FSO adds to bid list → Bid(status=draft)
      ↓
5. FSO submits bid → Bid(status=submitted)
      ↓
6. Bureau AO reviews → Bid(status=handshake_offered)
      ↓
7. FSO accepts → Bid(status=handshake_accepted)
      ↓
8. Panel review → Bid(status=in_panel)
      ↓
9. Final decision → Bid(status=approved) or Bid(status=declined)
```

## Security posture (post-hardening)

| Control | Implementation |
|---------|---------------|
| Session timeout (STIG V-220630) | 15-min inactivity via `SESSION_COOKIE_AGE` + `SESSION_SAVE_EVERY_REQUEST` |
| Token timeout (STIG V-220630) | 15-min inactivity via `TokenActivityMiddleware` refreshing `ExpiringToken.created` |
| CORS (NIST SC-8) | Env-configured `CORS_ALLOWED_ORIGINS` whitelist |
| HSTS (STIG V-220634) | 1-year `Strict-Transport-Security` with `includeSubDomains` and `preload` |
| Security headers (STIG V-220641) | `SecurityHeadersMiddleware`: CSP, X-Content-Type-Options, Referrer-Policy, Permissions-Policy |
| Cookie security (STIG V-220630) | `Secure`, `HttpOnly`, `SameSite=Lax` on session and CSRF cookies |
| Crypto (NIST SP 800-131A) | SHA-256 for cache keys; MD5 eliminated |
| Exception handling | Bare `except:` clauses replaced with `except Exception:` across all modules |
